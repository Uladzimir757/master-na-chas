# CLAUDE.md — master-na-chas (Złota Rączka / «Мастер на час»)

Контекст для ЛЮБОЙ сессии Claude Code с этим репо — из чата, из терминала,
параллельной сессии. Мост между кодом и чатами: что узнала одна сессия,
должно быть видно следующей через этот файл. Обновляй его короткими
правками по ходу работы, не жди отдельного запроса.

## Что это

Своя букинг-платформа для «мастер на час» (2 мастера, Trójmiasto) — слоты и
календарь, а НЕ лид-маркетплейс (не как Fixly.pl). Отдельный продукт/бизнес
от [[zlecai]] (dispatcher) — тот универсальный AI-диспетчер лидов, ЭТОТ
проект — конкретная букинг-система с собственными мастерами и клиентами.
Спроектирован так, чтобы движок позже переиспользовался в Garage System при
необходимости: сущности (`tenant`/`provider`/`service`/`booking`) одинаковы,
разница в данных, не в коде. Отдельный репозиторий намеренно — см.
`docs/decisions.md`, не склеивать без явного решения.

## Стек и ключевые ID

- БД: Postgres (прод — Neon, строка подключения в `.env`), схема в

## Структура (см. README.md для деталей)

- `app/slot_engine.py` — доступность/слоты, таймзона Europe/Warsaw; там же
  константы `CONFIRM_WINDOW` (15 мин) и `CONFIRM_REMINDER_STEP` (5 мин).
- `app/notifications.py` — Telegram + Web Push + FCM мастеру, SMS (Twilio) +
  FCM клиенту; best-effort, не роняют запрос при сбое. Тексты пишет LLM
  (`app/llm_text.py`), код передаёт только purpose + facts.
- `app/security.py` — вход мастера: cookie-сессия + Bearer-токен (Safari/iOS
  режет межсайтовые cookie). Токен 30 дней, но `/auth/me` выдаёт свежий —
  приложение продлевает вход при каждом запуске, живёт до «Выход».
- Регистрация мастеров только через суперадмина (`X-Admin-Secret`), без
  публичной формы.
- `scripts/seed.py` — тенант + стартовая услуга + 2 мастера + рабочие часы.
- `scripts/seed_translations.py` — все UI-строки pl/en (`translation_entry`).
- `app/confirm_timer.py` — таймер подтверждения заказа, см. ниже.
- Города: `city`/`provider_city`, см. ниже.

## Продуктовые решения (не пересматривать без пользователя)

- **Подтверждение заказа — всегда ручное** (11.11.2026). Переключатель
  мастера «подтверждать вручную» убран из кабинета; `create_booking` всегда
  создаёт `pending`, колонка `provider.requires_booking_confirmation` больше
  не читается (PATCH settings её принимает от старых клиентов и игнорирует).
- **Таймер подтверждения** (`docs/confirm-timer-travel-cities-task.md`):
  15 минут, напоминания мастеру на 5-й и 10-й минуте, на 15-й — автоотмена
  (`cancel_reason='provider_timeout'`) и сообщение клиенту. Заказ вне рабочих
  часов ждёт их начала (ночью мастера не будим); ночной заказ на первый
  утренний слот — таймер сразу. Подтверждение после дедлайна — 409.
  Автоотмены в аналитике — отдельная колонка `timed_out`.
- **Время доезда** — мастер выбирает при подтверждении (15/30/45/60/90,
  обязательно, иначе 422), уходит клиенту в уведомлении. Только информация:
  календарь не блокирует, `travel_buffer_minutes` как был.
- **Города** — мастер выбирает несколько в кабинете (минимум один), клиент
  выбирает город первым шагом на главной (запоминается в localStorage) и видит
  только его мастеров. Существующие мастера при миграции получили Gdynia.
  `GET /api/providers` без `?city=` отдаёт всех — для старого кэша страницы.
  Справочник городов ведёт суперадмин в `/admin`.
- **Приложение одно** на мастера и клиента: сохранённый вход мастера сразу
  открывает `/cabinet/`, без него — главная для клиента.
- **Дизайн**: клиентские страницы — тёплая тема (`.theme-warm`, кремовый +
  зелёный #3E7D6B + янтарный), кабинет мастера и админка — спокойная мятная.
  Явное сохранение кнопкой, без молчаливого сохранения «по уходу с поля» —
  пользователь на это жаловался.

## Тариф Render и тик — что сделать при переходе на платный

API сейчас на **free tier** (засыпает без трафика, Cron Job недоступен).
Пользователь переведёт на платный тариф вместе с запуском рекламы.

- Сейчас работает: автоотмена через 15 минут — лениво, при первом обращении
  к API после дедлайна (перед выдачей слотов/календаря/брони/аналитики и
  перед созданием брони).
- Сейчас НЕ работает: напоминания на 5-й/10-й минуте и отложенное
  уведомление о ночном заказе в начале рабочего дня — их шлёт только тик.
- **При переходе на платный тариф** (код менять не нужно):
  1. В Render у `master-na-chas-api` задать env `TICK_SECRET` (случайная
     строка).
  2. Создать Render Cron Job раз в минуту:
     `POST https://master-na-chas-api.onrender.com/internal/tick` с заголовком
     `X-Tick-Secret: <TICK_SECRET>`. Без секрета эндпоинт отвечает 403.
  3. Тик идемпотентен (повторный вызов в ту же минуту ничего не дублирует).

## Процесс

- `git push` с этой машины работает. Пуш в `main` = автодеплой обоих
  сервисов, поэтому порядок: миграция на прод → пуш → сид переводов.
- Перед push — `git pull --rebase origin main` (не слепой force), если
  параллельно могла идти другая сессия/ветка.
- **Запись в прод-БД (Neon) — только с явного «да» пользователя** в чате:
  миграции, сиды, любые UPDATE.
- Миграции: Alembic нет. Новый файл `db/migrations/<дата>-<что>.sql`
  (идемпотентный), тот же текст дописать в `db/migrations/2026-10-ALL.sql`,
  и изменения — в `db/schema.sql` + `app/models.py` вручную.
- Переводы: новые ключи — в `web/lib/i18n.ts`, `scripts/seed_translations.py`
  и фикстуру `web/tests/mocks.ts`; на прод —
  `PYTHONIOENCODING=utf-8 venv/Scripts/python -m scripts.seed_translations`.
  До сида на проде вместо текста видны сырые ключи.
- Тесты: см. `tests/README.md`. Нужен реальный Postgres
  (`TEST_DATABASE_URL`, схема пересоздаётся из `db/schema.sql`). Локальный
  кластер поднимать с `-c lc_messages=C`: код ловит английское
  «exclusion constraint» в тексте ошибки, с русской локалью тесты на 409
  падают.
- Локальный стенд: порт 3000 занят другим проектом пользователя
  (`D:\allapp\dispatcher`) — не трогать; 8000 тоже занят. Использовать
  API на 8010, next dev на 3010.
- Python на Windows пишет файлы с CRLF — `.gitattributes` нормализует в LF,
  это не ошибка.
- Никогда не коммитить keystore и креды.
