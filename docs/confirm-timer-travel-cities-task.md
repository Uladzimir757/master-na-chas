# Таймер подтверждения заказа + время доезда + города мастера

Задание от 11.11.2026 (три пункта пользователя и его ответы на уточнения).

## Решения пользователя

| Пункт | Решение |
|---|---|
| 1. Время доезда | Мастер выбирает вручную в момент подтверждения заказа (15/30/45/60/90 мин). Авторасчёта по геолокации нет. |
| 2. Город | Мастер выбирает несколько городов из списка. Клиент видит только мастеров своего города. |
| 3. Срок подтверждения | 15 минут. Напоминания мастеру на 5-й и 10-й минуте. На 15-й — автоотмена + уведомление клиенту. |
| 3. Заказ вне рабочих часов | Таймер стартует с начала ближайших рабочих часов мастера. Ночью мастера не будим. |

## Решения по умолчанию (открытые вопросы, пользователь не уточнял)

1. Время доезда — только информация для клиента и мастера, на генерацию слотов не влияет
   (`travel_buffer_minutes` как был).
2. Существующие мастера привязываются к Gdynia.
3. Заказ ночью на первый утренний слот (дедлайн с рабочих часов получился бы не раньше
   начала слота) — таймер идёт сразу с момента создания.

## Как сделано

- **Таймер** — `app/confirm_timer.py`. Дедлайн хранится в `booking.confirm_deadline_at`,
  `confirm_notices_sent` (0..3) защищает от дублей уведомлений.
  - Истечение ленивое и идемпотентное (`expire_overdue_bookings`) — вызывается перед
    выдачей слотов, календаря, «моей записи», созданием брони и из тика.
  - Напоминания — `POST /internal/tick` с заголовком `X-Tick-Secret` (env `TICK_SECRET`).
    API на бесплатном тарифе Render (Cron Job там недоступен), поэтому тик раз в минуту
    дёргает внешний пингер (например cron-job.org). Без пингера автоотмена всё равно
    срабатывает при следующем обращении к API, но напоминания и отложенные «ночные»
    уведомления не уходят.
  - Подтверждение после дедлайна — 409 прямо в эндпоинте.
- **Время доезда** — `booking.travel_minutes`; `PATCH /api/bookings/{id}/status` со
  `status=confirmed` требует `travel_minutes` (иначе 422). Клиент получает его в
  уведомлении о подтверждении.
- **Города** — таблицы `city`, `provider_city`, `booking.city_id`.
  `GET /api/cities`, `GET /api/providers?city=<slug>`, `GET/PUT /api/providers/me/cities`,
  `GET/POST/PATCH /admin/cities`.

## Проверить руками после деплоя (нужен живой телефон)

- Заказ в рабочие часы → push сразу, напоминания на 5-й и 10-й минуте, на 15-й — отмена и
  сообщение клиенту, слот снова свободен.
- Заказ вне рабочих часов → ночью тишина, push в начале рабочего дня.
- Подтверждение → обязательный выбор времени доезда → клиент получил его в уведомлении.
- Убрать у мастера город → он пропал из выдачи этого города.
