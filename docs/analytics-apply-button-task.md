# Задание: кнопка «OK»/«Применить» на страницах аналитики

Жалоба пользователя: на странице «Analityka wykonanych prac» (аналитика в
кабинете мастера) нет кнопки подтверждения — и это подтвердилось в коде:
обе страницы аналитики подгружают данные через `useEffect` на каждое
изменение поля даты, без отдельного шага подтверждения. Решено: добавить
кнопку, не оставлять как есть.

## Где менять

1. `web/components/AnalyticsPanel.tsx` — аналитика в кабинете мастера
   (`t.analyticsTitle` = «Analityka wykonanych prac», локализована pl/en).
2. `web/components/AdminAnalytics.tsx` — аналитика в суперадминке (сейчас
   захардкожена по-русски, не через `t.*` — оставить так же, не затрагивать
   локализацию в рамках этой задачи).

Обе сейчас устроены одинаково: `from`/`to` (и в админке — `providerId`)
меняются через `onChange` → сразу уходит запрос в `useEffect`.

## Что сделать

- Запрос должен уходить **только по нажатию кнопки**, не на каждое
  изменение поля — убрать автозапрос из `useEffect` по смене `from`/`to`
  (и `providerId` в админке), оставить только начальную загрузку при
  монтировании (с дефолтным периодом, как сейчас — последние 30 дней).
- Добавить кнопку (компонент `CompactButton` из `web/components/ui.tsx`,
  он уже используется в похожих местах — единый стиль кнопок на сайте).
  Текст — новый i18n-ключ в `AnalyticsPanel.tsx`
  (например `analyticsApply`: pl «Zastosuj», en «Apply» — завести в
  `scripts/seed_translations.py` рядом с остальными `analytics*`-ключами,
  строка ~424); в `AdminAnalytics.tsx` — захардкоженная русская строка
  «Применить», как остальной текст этого компонента.
- Кнопка неактивна (`disabled`), если `to < from` или одно из полей пустое
  — так же, как сейчас молча пропускается запрос в этом случае.
- Нажатие Enter в любом из полей даты должно тоже запускать применение
  (как обычно ожидается от формы с кнопкой подтверждения) — удобно
  обернуть поля в `<form onSubmit={...}>` с `e.preventDefault()`.
- Сохранить лоадер/состояние ошибки как сейчас (`error`, `calendarLoadError`).

## Проверка

- Плейрайт-тесты, если есть на эти компоненты (`web/tests/*analytics*` —
  проверить, есть ли), обновить под новое поведение (запрос только после
  клика/submit, не после каждого `fill`).
- Живая проверка: сменить дату несколько раз без нажатия кнопки — запрос не
  должен уходить (смотреть Network); нажать кнопку — данные обновляются.
